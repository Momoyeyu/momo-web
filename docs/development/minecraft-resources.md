# Minecraft resources and remaining account prerequisite

The Fabric component builds with Java 21 and Gradle 8.10.2 through `scripts/build-minecraft-component.py --gradle /qualified/gradle --cache /isolated/cache`. The script verifies the Gradle version, builds with an isolated cache, and reports the output SHA256. Generated jars remain ignored.

`backend/app/services/minecraft_resources.py` qualifies a maintainer-prepared local resource closure and copies it into a new, dedicated instance. A schemaVersion 1 manifest contains exact `pins` (Minecraft 1.21.1, loader 0.16.14, fabricApi 0.116.4+1.21.1, java 21), `files` entries with relative path/SHA256, `classpath` jar paths, and `mainClass: net.fabricmc.loader.impl.launch.knot.KnotClient`. Companion jar must be present. Existing instances are never overwritten. This manifest is trusted release input, not user/model-supplied code; hashes verify integrity, not safety or licensing. Qualification does not prove that every vanilla asset/native/library dependency is present. A product release still needs an official metadata resolver and platform-specific closure acceptance.

There is currently no managed launch/login button enabled: resource preparation is implemented, but launch fails explicitly without a legitimate session provider. No offline-account fallback, token borrowing, or official-client impersonation is implemented. A single owned instance lifecycle object provides resource preparation/status/stop; it is not a second plugin system. User-facing settings should report login unavailable until the following prerequisite is supplied and integrated.

Microsoft device code flow requires a registered public client application. The product maintainer must register momo, support the intended personal Microsoft accounts, and enable the appropriate public client flow. See [Microsoft flow documentation](https://learn.microsoft.com/en-us/entra/identity-platform/msal-authentication-flows). A desktop public client does not keep a client secret. A registration alone is not evidence of Minecraft entitlement access: verify Xbox and Minecraft token exchange, Java ownership/profile, and refresh/revocation with a consenting test account before enabling launch.

[Prismarine Auth's API](https://github.com/PrismarineJS/prismarine-auth/blob/master/docs/API.md) supports an owned client ID via `authTitle` and `flow: 'msal'`. Its documented `live` flow and exported official app IDs are not an acceptable shortcut for momo. The library is a potential implementation dependency; it is not installed or configured here and no login requests were made. Once integrated, credentials must stay in private storage and excluded from logs, backups, UI status and command lines; the bridge token should be generated internally per instance rather than entered by users.
